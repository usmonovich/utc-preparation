# Этап 1. Техническое задание и архитектура

Проект: **«UTC Preparation»** (до 24.10.2026 — «Физика по конспекту») — мобильное приложение для подготовки к вступительному экзамену по физике и математике.
Версия документа: 1.1 (24.10.2026; разделы 1–… — исходное ТЗ физики от 16.10.2026, раздел «UTC Preparation» — расширение). Владелец материалов и администратор: Husniddin.

## UTC Preparation: два предмета (расширение от 24.10.2026)

- **Стартовый экран** — выбор предмета: «Физика» (значок атома) и «Математика» (π). Адреса: `#/` — выбор, `#/p/…` — физика, `#/m/…` — математика; старые адреса без префикса открывают физику.
- **Физика** сохранена без изменений: та же учебная база (байт в байт), те же ключи хранилища (`fpk.user.v1`, `fpk.admin.v1`) и документы базы артефакта (`fpk/admin`, `data/users/<id>/state`), поэтому прогресс, история тестов, избранное и решения проверки сохраняются.
- **Математика** — своя учебная база (`content/math/pack.json`) и свои хранилища (`utc.math.user.v1`, `utc.math.admin.v1`; в артефакте — `fpk/math`, `data/users/<id>/math`). Экраны, тесты (по теме, подразделу, разделу, нескольким разделам; по порядку и случайно; выбор количества; подсказка → повтор → разбор; экзамен с таймером), карточки, избранное, повторение ошибок, статистика, поиск — общий код с физикой. Настройки (тема, шрифт) и PIN администратора — общие.
- **Порядок курса** — оглавление книги «Математика. Сборник тестовых заданий для абитуриентов. Отсортировано по темам», части 1 (1996–2005) и 2 (1996–2009): 2 раздела, 31 глава, 131 пункт. Пункты, ещё не наполненные, видны в плане курса со статусом «извлечено».
- **Этапы темы:** извлечено → подготовлено → требует проверки → проверено (поле `stage`); дальше по каждой записи — «на проверке» → «утверждено» (админ-панель) → «опубликовано» (версия на сервере).
- **Источники темы:** «Моя книга» (часть, пункт, страницы) и «Дополнительные источники» (название, организация, ссылка, дата проверки). Теория и задания написаны своими словами по открытым источникам; задания книги не копируются (авторское право), изображения страниц книги в приложение не встраиваются.
- **База данных (Supabase):** миграция `0002_subjects.sql` добавляет столбец `subject` в `sections`, `source_files`, `content_versions`; прогресс пользователей хранится в прежних таблицах — ID математики начинаются с `ma-` и не пересекаются с физикой.

## 1. Техническое задание

### 1.1 Цель
Превратить загружаемые учебные материалы (PDF, фото, сканы, документы) в структурированный курс: теория → формулы → примеры → вопросы → тесты → результаты. Только на основе материалов владельца, с указанием источника для каждой записи.

### 1.2 Пользователи и роли
| Роль | Возможности |
|---|---|
| Студент (гость, без аккаунта) | Всё обучение и тесты офлайн, прогресс хранится на устройстве |
| Студент (с аккаунтом) | То же + синхронизация прогресса между устройствами |
| Администратор | Импорт файлов, проверка и утверждение записей, правка структуры, публикация, резервные копии |

### 1.3 Функциональные требования (сводка)
- **Обучение по темам:** теория, определения, законы, формулы с расшифровкой обозначений и единиц СИ, условия применимости (если указаны в источнике), примеры с решениями, вопросы для самопроверки; отметка «изучено»; переход между темами; возврат к последней теме.
- **Тесты трёх уровней:** тема → подраздел → раздел(ы)/весь курс. Настройки: область, темы, количество, типы заданий, порядок (A «По порядку» / B «Случайный»), лимит времени.
- **Алгоритм ответа:** верно → объяснение; неверно → подсказка из источника → повторная попытка → при второй ошибке полный разбор. Кнопка «Показать решение». Блок «Объяснение ответа» с источником после каждого вопроса.
- **Типы заданий:** один ответ, несколько ответов, числовой (с допуском и единицами), соответствие, последовательность, текстовый ответ (самопроверка по эталону), выбор формулы.
- **Режимы:** вопрос–ответ, карточки, повторение ошибок, избранное, экзамен, тренировка формул, практика задач, повторение пройденного.
- **Прогресс:** общий и по разделам/подразделам/темам, история попыток, % правильных, слабые темы, динамика по периодам, сброс с подтверждением.
- **Админ-панель:** импорт, отчёт обработки, очередь проверки, правка, утверждение/отклонение, структура, публикация, дубликаты, проверка ссылок на источник, экспорт/импорт базы, журнал ошибок обработки, список исправлений (errata).
- **Интерфейс:** светлая/тёмная тема, поиск (темы, формулы, вопросы), адаптация под телефоны и планшеты, доступность (контраст, масштаб шрифта, подписи для экранных чтецов).

### 1.4 Нефункциональные требования
- Работа офлайн для загруженного контента и прогресса.
- Никаких секретных ключей в клиенте (anon-ключ Supabase — публичный по дизайну, доступ ограничен RLS).
- Учебная база — структурированные данные (JSON-пакет контента + таблицы Postgres), не код.
- Расширяемость: новые разделы/темы/файлы без изменения логики приложения.
- Обновление контента без потери истории результатов (стабильные ID записей, версионирование пакета).

### 1.5 Правила контента (из промпта, обязательны)
1. Источник — только материалы владельца. Ничего не добавляется «из памяти».
2. Нечитаемое/неоднозначное помечается `[?]` и уходит на проверку.
3. Ошибки в источнике не исправляются молча: оригинал сохраняется, исправление предлагается отдельно (`errata`).
4. У каждой записи — ссылка на источник: файл, страница, фрагмент.
5. Сгенерированные вопросы помечены `generated: true`, имеют статус `review` и не попадают в тесты до утверждения.
6. Уровни сложности не вводятся: материалы не дают для них основания.

## 2. Архитектура

```
┌──────────────────────── Клиент (React + TS, PWA / Capacitor) ────────────────────────┐
│ UI (screens, components)                                                              │
│   └─ использует ──► Domain (чистый TS, без UI):                                       │
│                      test-engine · answer-check · hint-flow · progress · search       │
│ Data layer:                                                                           │
│   ContentRepository  ◄── пакет контента (JSON, встроен в приложение) + оверлей админа │
│   ProgressStore      ◄── локальное хранилище (localStorage / Capacitor Preferences)   │
│   SyncAdapter        ◄── Supabase REST (только если настроен)                         │
│ Admin (отдельный раздел, защищён ролью/PIN)                                           │
└───────────────────────────────────────────────────────────────────────────────────────┘
             │ HTTPS (anon key + JWT пользователя, RLS)
┌────────────▼──────────── Supabase ────────────────────────────────────────────────────┐
│ Auth (email+пароль) · Postgres (схема контента + прогресса, RLS) · Storage (файлы)    │
│ Edge Functions: import-file (OCR через серверный ключ), publish-pack                  │
└───────────────────────────────────────────────────────────────────────────────────────┘
             │
┌────────────▼──────────── Конвейер импорта (tools/import, Node + Python) ──────────────┐
│ PDF/фото → страницы → разрезка разворотов → OCR (Tesseract для печати /               │
│ vision-модель для рукописи) → транскрипт с ссылками → структурирование →              │
│ валидатор пакета (схема, источники, LaTeX, числовые проверки, дубли) → отчёт → review │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

Разделение ответственности (требование п. 11): UI / бизнес-логика (`src/domain`) / учебная база (`content`, таблицы `content_*`) / система тестирования (`src/domain/test-engine.ts`) / импорт (`tools/import`, `supabase/functions/import-file`) / авторизация (`src/data/auth.ts`) / статистика (`src/domain/progress.ts`) / синхронизация (`src/data/sync.ts`) / админ-инструменты (`src/admin`).

## 3. Выбор технологий

| Слой | Выбор | Почему |
|---|---|---|
| Клиент | **React 19 + TypeScript** | Один код для веба, Android, iOS; зрелая экосистема |
| Формулы | **KaTeX** | Быстрый и точный рендер LaTeX без сети; корректные индексы, дроби, греческие буквы; горизонтальная прокрутка длинных формул на узких экранах |
| Сборка | **esbuild** | Быстрая production-сборка, без лишних зависимостей |
| Мобильные сборки | **Capacitor 7** | Оборачивает тот же веб-код в нативные проекты Android Studio / Xcode, публикация в Google Play и App Store |
| Бэкенд | **Supabase** (Postgres 15+, Auth, Storage, Edge Functions) | Бесплатный тариф для старта; реляционная схема; Row Level Security; нет своего сервера |
| Офлайн | Контент встроен в сборку; прогресс — локально, синхронизация при наличии сети | Обучение и тесты работают без интернета |
| Тесты | node:test (unit), Playwright (e2e, мобильные вьюпорты), Postgres 16 (миграции и RLS) | Всё запускается локально |

**Почему не Flutter (рассмотрен как начальный вариант).** (1) В среде разработки нет доступа к Flutter SDK и пакетным реестрам — Flutter-код нельзя было бы собрать и протестировать, что противоречит правилу «не выдавать непроверенный код за готовый». (2) Рендер формул: KaTeX в вебе надёжнее, чем Flutter-пакеты для LaTeX (`flutter_math_fork`), особенно для сложных дробей и корней. (3) Админ-панель и приложение используют один и тот же код и одни и те же компоненты формул. Цена решения: производительность WebView немного ниже нативной — для учебного приложения с текстом и формулами это несущественно.

## 4. Структура разделов (по фактическим материалам)

Исходная классификация из 5 разделов сохранена как каркас, но **создан только раздел с материалами**. Предлагаемое уточнение подразделов механики (согласовать):

**1. Механика**
1. **Кинематика** — основные понятия; виды движения и средняя скорость; равномерное движение и графики; векторы, переправа; ускорение и равнопеременное движение; относительная скорость; путь в равнопеременном движении; уравнение движения; свободное падение; бросок вверх; движение по окружности; центростремительное ускорение и передачи; горизонтальный бросок; бросок под углом.
2. **Динамика** — основные понятия (масса, объём, плотность, сила); равнодействующая; законы Ньютона; виды сил; сила упругости и пружины; гравитация; спутники; вес, перегрузка, невесомость; динамическое уравнение и связанные тела; трение; наклонная плоскость; сопротивление; системы тел и сила под углом.
2а. **Статика** *(в конспекте только названа в плане курса, стр. p01; подраздел составлен по материалам из интернета по просьбе владельца)* — момент силы, условия равновесия, рычаг; рода рычагов, рычаг с собственным весом и системы рычагов; блоки и полиспаст; наклонная плоскость, ворот, золотое правило механики и КПД; центр тяжести (центр масс) и устойчивость; виды равновесия; сложные задачи на равновесие (балка на опорах, стержень на шарнире, лестница) — расширено 22.10.2026.
3. **Механика жидкостей и газов** *(в исходном списке — «Статика»; в конспекте статика твёрдых тел (моменты сил, рычаг) отсутствует, а есть гидро- и аэростатика и гидродинамика)* — давление; закон Паскаля и гидростатическое давление; сообщающиеся сосуды; атмосферное давление; гидравлический пресс; закон Архимеда; плавание тел и подъёмная сила; движение жидкости в трубах.
4. **Законы сохранения** — импульс тела; импульс силы и удары; механическая работа; кинетическая энергия; потенциальная энергия; закон сохранения механической энергии; гравитационная потенциальная энергия и II космическая; упругое столкновение; закон сохранения энергии с трением; мощность и КПД.

**1а. Механические колебания и волны** (в разделе «Механика», из конспекта по магнетизму, стр. e09–e15) — колебания, маятники, энергия колебаний, волны, звук.

**2. Молекулярная физика и термодинамика** — МКТ и идеальный газ; термодинамика; свойства твёрдых тел и жидкостей (включая влажность воздуха).

**3. Электродинамика и электромагнетизм** — электростатика; электроёмкость и конденсаторы; постоянный электрический ток (стр. c01–c35); электрический ток в различных средах и диод (стр. c36–c40, e01); магнитное поле; электромагнитная индукция; электромагнитные колебания и волны (колебательный контур, переменный ток, трансформатор, ЭМВ — стр. e20–e28, радиоволны — стр. o01).

**4. Оптика** — геометрическая оптика; линзы и оптические системы; волновая оптика (интерференция, дифракция и дифракционная решётка — по фото d01–d02, дисперсия); элементы теории относительности *(в исходной классификации места нет; в конспекте идёт после дисперсии — предложение: оставить здесь или перенести, согласовать)*.

**5. Квантовая и ядерная физика** — фотон и фотоэффект (из конспекта по оптике, стр. o12–o14); строение атома (модель Резерфорда, постулаты Бора), атомное ядро (нуклоны, изотопы, энергия связи), ядерные реакции и радиоактивность (стр. a01–a08; тема «Радиация» и второй постулат Бора дополнены из интернета).

Разделы идут в порядке исходной классификации: электродинамика стоит перед оптикой независимо от того, какой конспект загружен раньше. Структура редактируется в админ-панели без изменения кода.

## 5. Схема базы данных

Полная схема — `supabase/migrations/0001_schema.sql`. Сущности (все из п. 13 промпта):

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `users` → `profiles` | профиль поверх `auth.users` | `id`, `display_name`, `role (student/admin)` |
| `sections`, `subsections`, `topics` | иерархия курса | `id`, `parent_id`, `title`, `sort_order`, `status` |
| `source_files` | загруженные файлы | `sha256` (защита от дублей), `kind`, `pages_total`, `import_status` |
| `source_pages` | страницы | `file_id`, `page_ref` (`p14L`), `image_path`, `ocr_confidence`, `readable` |
| `source_fragments` | фрагмент страницы | `page_id`, `text`, `bbox` |
| `theories` | блоки теории | `topic_id`, `kind`, `body_md`, `source_refs`, `status`, `source_order` |
| `formulas` | формулы | `latex`, `symbols jsonb`, `conditions`, `boxed`, `needs_manual_check` |
| `examples` | разобранные примеры | `given`, `steps jsonb`, `answer` |
| `questions` | вопросы | `type`, `prompt`, `generated`, `status`, `source_order`, `content_hash` |
| `answer_options` | варианты | `question_id`, `key`, `body` |
| `correct_answers` | эталон | `value jsonb`, `tolerance`, `unit` |
| `explanations`, `hints` | разбор и подсказки | `body_md`, `formula_ids`, `level` |
| `test_configurations` | сохранённые настройки теста | `scope jsonb`, `count`, `order_mode`, `types`, `time_limit` |
| `test_attempts`, `attempt_answers` | попытки и ответы | `config`, `question_ids`, `seed`, `tries`, `hint_used`, `correct` |
| `user_progress` | прогресс по темам | `topic_id`, `studied_at`, `last_opened_at` |
| `bookmarks` | избранное | `entity_type`, `entity_id` |
| `error_review_queue` | ошибки для повторения | `question_id`, `wrong_count`, `next_due_at` |
| `errata` | замечания к источнику | `page_ref`, `original`, `issue`, `suggested_fix`, `resolution` |
| `processing_log` | журнал импорта | `file_id`, `level`, `message` |

Статусы записей: `draft → review → approved | rejected`; опубликованные версии контента — `content_versions`.

## 6. Экраны и пользовательские сценарии

**Экраны студента:** Главная (продолжить, разделы, тестирование, ошибки, избранное, прогресс, настройки, поиск) · Раздел → Подраздел → Тема · Тема/обучение (теория, формулы, примеры, самопроверка, источник) · Страница конспекта (фото оригинала) · Настройка теста · Прохождение теста · Результаты · Режимы (карточки, вопрос–ответ, экзамен, тренировка формул, практика задач, повторение пройденного, ошибки) · Избранное · Прогресс · Поиск · Настройки · Вход/регистрация (если включён бэкенд).

**Экраны администратора:** Обзор и отчёты импорта · Очередь проверки · Редактор вопроса · Проверка теории/формул · Замечания (errata) · Структура курса · Дубликаты · Проверка источников · Экспорт/импорт и резервные копии · Журнал обработки.

**Ключевые сценарии:**
1. Новый пользователь → Главная → Разделы → Механика → Кинематика → тема → читает теорию и формулы → «Изучено».
2. Тест по подразделу: Тестирование → Кинематика → 20 вопросов → «По порядку» → ошибка → подсказка → повтор → разбор → результаты → ошибки попадают в «Повторение ошибок».
3. Экзамен: весь курс, 30 вопросов, 30 минут, случайный порядок, подсказки отключены, разбор в конце.
4. Администратор: импорт файла → отчёт → очередь проверки → правка/утверждение → вопросы появляются в тестах.

## 9. Проверка корректности извлечённых материалов

1. **Двойная привязка:** каждая запись хранит `page_ref`; в приложении у записи кнопка «Источник» открывает фото страницы — администратор сверяет глазами.
2. **Статусы:** всё извлечённое импортируется со статусом `review`; сгенерированное — `generated: true` + `review`.
3. **Автоматический валидатор пакета** (`tools/validate-content.ts`): уникальность ID, существование страниц-источников, рендер каждой формулы KaTeX без ошибок, все обозначения формул есть в словаре, у каждого вопроса есть подсказка, объяснение и источник, корректность правильных ответов по типу.
4. **Числовые контрольные примеры:** каждый расчётный вопрос содержит выражение `check`, валидатор пересчитывает ответ независимо и сравнивает с эталоном; отдельные unit-тесты пересчитывают примеры из конспекта (например, $p_{ат} = 13600\cdot9{,}81\cdot0{,}76 = 101\,396{,}16$ Па, $\upsilon_I = 7905$ м/с).
5. **Errata:** подозрительные места источника вынесены в отдельный список с исходным текстом, проблемой и предложением — решение принимает владелец.
